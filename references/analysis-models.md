# 深度分析模型

只提取当前目标人物和关系中可观察到的模式。证据支持结论，但不授权诊断，也不能证明对方当前仍然如此。

## 确定性统计与语义推理的边界

程序可计算数量、长度、时间范围、标点、burst 和 token 频率。以下内容必须由模型逐块读取原始消息后完成，不能由关键词或模板代替：

- 谁做了什么、事情是否发生；
- 身份事实和关系变化；
- 精确日期与日期精度；
- 语气、行为、反应序列和停止点；
- 反例、矛盾、阶段变化；
- 示例的场景含义与代表性。

每个分块只进入一个模型上下文。分块摘要必须具体到当前分块；不能重复通用结论来填满字段。

## 身份、关系与时间线

提取已经确认的身份事实、关系里程碑、共同日常、重复偏好、重要变化、冲突主题、修复尝试和未来计划。明确区分：

- 目标人物明确陈述；
- 用户明确陈述；
- 关系层面观察；
- 分析者推断；
- 尚未解决的矛盾。

每个事件记录：

- event／milestone 类型；
- 发生日期及 `day|month|year|period|unknown` 精度；
- `confirmed|discussed|planned|inferred|unknown` 历史状态；
- 证据角色、evidence_id、反证和置信度。

区分“历史上已确认”与“现实当前仍然成立”。当前状态未知时，仍须保留证据明确的历史日期。区分“讨论过”“计划过”和“已经完成”。避免不必要的第三方、财务、医疗、账号、工作机密和私密细节。

## 用行为表达 Persona

不要停留在温柔、软弱、嫉妒、回避或关心等形容词。使用条件行为：

```text
当情境 X 出现时，目标人物通常先做 Y，随后可能做 Z；反例或停止点是 W。
```

保留反例。频繁道歉不能证明顺从；表达边界不能证明敌意；压力下低活跃不能证明情感疏离。

## 沟通风格

结合确定性统计和逐块语义观察分析：

- 仅目标人物消息的长度分布；
- 连续目标消息 burst；
- 句子碎片和消息拆分；
- 词汇、称呼、程度副词、重复词、标点和提问方式；
- emoji／表情包／token 的选择与组合；
- 普通、亲密、压力与冲突消息的差异；
- 随时间发生的阶段变化。

统计必须声明样本量、分母、发送者、排除规则和时间覆盖。确定性计数可以批量完成，但“为什么在该场景使用”必须由语义证据支持。

## 平台 token 语义

短格式 `[名称]` 在类似微信的文本中通常表示 emoji 或表情包 token。图片、通话、链接、文件、转账和撤回等媒体或系统占位符不属于情绪 token。

分别分析：

1. 某场景中是否选择 token；
2. 选择后的 token 名称或组合；
3. 选择后重复数量；
4. 独立消息、前缀、后缀或文字混合；
5. 相邻 turn 中的重复与抑制；
6. 上下文含义和歧义。

绝不能根据已包含 token 消息中的数量分布，推导每轮都追加 token。未知 token 只作为低置信上下文信号，不得虚构其视觉画面。

## 反应与行为模式

有证据时建模：

- 普通开场与重新进入；
- 亲密与轻松撒娇；
- 开心与夸赞；
- 关心与实际支持；
- 安慰与情绪倾听；
- 不耐烦与生气；
- 第三方边界；
- 冲突升级、暂停、媒介切换和修复；
- 道歉与接受道歉；
- 拒绝、隐私和自主权；
- 压力、疲劳、工作、旅行与低容量联系。

每个模式记录触发条件、第一反应、反应序列、长度／节奏、具体行动、停止点、反例、日期范围、evidence_id 和置信度。

## 开场模型

独立测量问候长度、称呼、emoji、首个问题类型、burst 大小和长间隔重入。纯问候不自动添加助手式欢迎或主持问题。没有专项样本时，明确说明规则由更广泛统计迁移，不能伪装成高置信发现。

## 真实短语境 Few-shot

示例单位不是孤立句子，而是经过验证的相邻“用户 → 目标人物回复 burst”。令 `E` 为符合发送者、顺序、相邻性和隐私条件的有效 turn 数：

```text
Q = 0                                      当 E = 0
Q = min(E, min(24, max(3, round(sqrt(E/100)))))  当 E > 0
```

使用四舍五入。约 1,000 个有效 turn 选 3 条，约 10,000 个选 10 条，较大档案最多 24 条。

选择规则：

- 优先代表性、可迁移性和场景覆盖，不追求猎奇；
- 跨时间段取样，避免全部来自高活跃月份；
- 先覆盖主要反应模式，再允许同一场景第二条；普通情况下同一场景最多 2 条；
- 每条通常保留 2–6 条相邻消息，总可见字符默认不超过 240；
- 删除无关前后文、第三方、账号、金额、链接、健康、工作机密和其他高敏内容；
- 不能通过拼接不相邻消息制造示例；
- 用户必须看到候选场景、数量、隐私等级和拟保留原文，并明确批准后才能写入最终 Skill。

`verified-examples.md` 保存已批准的真实短语境、场景和反应特点，不保存 evidence_id。完整 `example_id → evidence_id → 源哈希` 映射只保存在 `final/audit/example-selection.json`。

若用户不批准原文，停止封装并说明缺少运行时真实示例；不得静默改用大量裸 evidence_id 或把释义冒充真实 few-shot。

## Anti-AI 模型

识别语义友善但与目标人物不一致的输出。以下类别只能通过数据和真实测试确认：

- 通用心理咨询话术；
- 脱离具体事件的泛化夸赞；
- 客服式问题；
- 冗长编号建议；
- 无限陪伴承诺；
- 强行乐观；
- 重复称呼或 token；
- 软化明确拒绝；
- 因亲密回暖而宣布冲突已经解决。

从当前人物证据构建替代表达。目标是预测下一条消息；自然 burst 完成后立即停止。

## 置信度

- **高**——重复独立证据，或一个无歧义明确陈述。
- **中**——多个一致观察但覆盖有限，或可信用户输入。
- **低**——稀疏、有歧义、阶段限定或推断性证据。

不得把低置信风格提升为运行时硬规则。不能用“当前未知”抹去高置信历史事件。
