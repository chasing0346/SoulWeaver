# Intake 与范围

读取消息正文前必须完成 intake。只有在不泄露内容且范围位于用户指定位置内时，才允许执行存在性检查和文件大小检查。用户确认授权该位置后，可以执行仅限元数据的发现扫描，检查 CSV／聊天表头和发送者标识字段，以便选择目标人物。

## 引导式 Create 对话

当用户只调用 `$soulweaver`，且没有指定操作或运行路径时，进入引导式 Create intake，不要一次询问所有设置。

### 第一次交互：数据源与授权

用一个简短提示同时请求绝对路径和授权。推荐提示：

> 请发送聊天记录文件或目录的绝对路径，并确认你有权访问和使用这些记录、授权我为本次人物 Skill 蒸馏处理它们。只提供路径时，我会先列出候选文件，不会读取聊天正文。

如果用户只回复路径，不得把它视为授权。可以列出该路径中的非内容元数据，再询问缺失的授权。如果回复中含有明确授权声明，继续确定源文件。

对于目录，默认只检查第一层文件。列出受支持的候选聊天导出文件，并取得准确的已展示白名单。如果存在多个可能的数据源，询问哪些文件属于同一段对话；不能仅因为它们位于同一目录就自动合并。

### 仅元数据的发送者发现

取得授权并确定数据源后，只检查识别格式和列出发送者所需的信息：

- 文件名、大小、扩展名、必要时的编码，以及表头名称；
- 发送者 ID 或发送者名称字段；
- 不读取消息文本、附件说明、引用消息、转写文本或链接内容字段。

不得输出聊天片段。去重发送者标识，并将候选标记为 `A`、`B` 等。如果多个标识可能属于同一人物，展示这种不确定性，不能擅自合并。如果没有可靠发送者字段，展示相关表头，并询问用户哪个字段／值对应各参与者。

### 第二次交互：目标与范围确认

用一个紧凑确认块展示：

- 候选发送者；
- 准确可读文件；
- 自动排除项；
- 准确的拟定工作区；
- 拟定目标显示名、输出显示名和调用 slug；
- 默认自动使用 `3` 个 `gpt-5.6-luna`、`max` reasoning effort 分析 subagent；若宿主槽位不足则使用可用最大并发并动态补充；用户可以要求降低并发或改为顺序执行；
- 是否允许最终 Skill 包含少量经过隐私审查的真实相邻短语境；默认不允许，只在草稿阶段展示候选；
- 仅生成草稿的状态。

要求用户回复 `A，确认` 等内容。说明该回复会选择候选 A，并确认刚刚展示的范围。如果所选发送者没有可用显示名，或无法生成有效调用 slug，只询问缺失的名称或 slug，不重复整个 intake。

收到该回复后，才允许处理消息正文。初始化前不得重复索取同一确认。

## 必需 intake 信息

收集并总结：

1. **授权**——确认用户可以访问和使用相关材料，并授权本次处理。
2. **可读范围**——准确源文件路径。目录可用于发现，但最终范围必须列出实际批准的聊天导出文件。
3. **排除项**——不得打开的同级目录、媒体、压缩包、文档、可执行文件、账号、第三方对话或其他材料。
4. **可写范围**——准确分析工作区；后续还包括拟定的生成 Skill 目录。
5. **目标身份**——当前运行使用的显示名或代号；它不会自动成为最终调用 slug。
6. **发送者映射**——哪些发送者标识属于目标人物、用户、群组参与者、机器人或未知发送者。
7. **关系／背景**——理解对话所需的最低限度背景。引导式 Create 中此项可选；未知背景必须保持未知，不能阻塞分析或被猜测。
8. **输出名称**——用户选择的 Skill 显示名和拟定的小写连字符 slug。两者都要复述并确认。
9. **执行模式**——默认目标为 `3` 个 `gpt-5.6-luna`、`max` reasoning effort 并行分析 subagent；记录用户是否要求降低并发或改为顺序执行，以及当前请求只生成草稿还是允许在后续确认后安装。
10. **真实短例授权**——区分“允许分析原文”和“允许把少量原文写入最终 Skill”。前者不自动包含后者。记录用户是否允许展示候选、是否允许封装，以及用户明确排除的内容类型。

## 范围记录

在分析工作区中把已确认 intake 保存为 `scope.json`，包括：

- `run_id`；
- `authorized_at`；
- `read_allowlist`；
- `read_denylist`；
- `write_allowlist`；
- 目标人物和发送者映射；
- 输出显示名和 slug；
- subagent 配置，包括是否启用、目标数量、模型、reasoning effort 和宿主可用并发不足时的降级策略；
- 真实短例授权状态；未授权时必须为 `false`，不能根据一般数据处理授权推断；
- 用于污染扫描的已知禁用标识；
- 用户提供的事实，并明确标记为用户输入。

不得在 `scope.json` 中保存聊天片段。

## 命名规则

- 不得复用先前运行、教程、示例、已安装 Skill 或当前模型记忆中的名称。
- 未提供名称时必须询问，不能静默编造。
- 调用 slug 只能使用小写 ASCII 字母、数字和单个连字符；不能以连字符开头或结尾，也不能包含连续连字符。
- 显示名可以使用用户偏好的大小写或语言。
- 如果请求的显示名不能直接作为 slug，提出规范化 slug 并取得确认。

## 确认消息

读取消息正文前，明确说明：

- 将读取的准确文件；
- 不会读取的路径；
- 准确可写工作区；
- 目标发送者映射；
- 拟定输出名称；
- 已批准的 Agent 模式。
- 真实短例当前仅生成候选还是允许封装；最终动态配额需要等标准化后根据有效相邻 turn 数计算。

只有用户确认该摘要后才能继续。

在引导式 Create 中，可以把候选目标选择和范围摘要合并。只有前一条消息完整且无歧义地展示了以上全部项目时，用户的 `A，确认` 类回复才足够。
